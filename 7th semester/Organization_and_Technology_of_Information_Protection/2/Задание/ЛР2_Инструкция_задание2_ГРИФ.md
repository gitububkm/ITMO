# Инструкция: задание №2 — расчёт рисков в системе ГРИФ

Пошаговое руководство по выполнению **задания 1.2 / №2** лабораторной работы №2 по дисциплине «Организация и технология защиты информации»: расчёт риска информационной системы в подсистеме **ГРИФ** комплекса **Digital Security Office**.

Исходные данные для ввода в программу берите из бланка (ресурс «Сервер», 3 угрозы × 2 уязвимости, значения `P(V)` и `ER`). После каждого ключевого шага делайте скриншот и вставляйте его в отчёт в отмеченные места.

---

## 0. Что подготовить заранее

1. Дистрибутив из папки задания:
   - `dsoffice2006_pe_demo.msi` / `.zip` / `.rar`
2. Виртуальную машину с **Windows XP** (как указано в методичке) или совместимую Windows, где демо запускается.
3. Таблицу исходных данных (см. раздел 8 ниже) — её удобно держать открытой рядом с ГРИФ.
4. Папку для скриншотов, например `screenshots_grif/`.

> Если на хосте macOS/современной Windows демо не ставится — используйте VM с XP и установку из `.msi` внутри гостевой ОС.

---

## 1. Установка и запуск

1. Скопируйте дистрибутив на ВМ.
2. Установите **Digital Security Office** (PE Demo) через установщик.
3. При необходимости запустите **сервер Digital Security Office** (в трее/через меню; значок должен стать «активным»).
4. Запустите клиент **ГРИФ** (Grif / Digital Security Office → ГРИФ).

**Скриншот для отчёта:** окно запуска / выбор алгоритма.

---

## 2. Создание проекта

1. В стартовом окне выберите алгоритм:
   - **«Анализ модели угроз и уязвимостей»**
2. Нажмите **«Создать проект»**.
3. Задайте имя проекта, например: `ЛР2_Расчет_рисков_Сервер`.
4. Откройте **Проект → Свойства проекта** и заполните:
   - ФИО ответственного;
   - должность;
   - краткое описание (учебный проект ЛР2 ОиТЗИ).

Режим расчёта для бланка:
- **одна базовая угроза (суммарная)**;
- критичность/риск — **в денежных единицах** (критичность ресурса = **100 у.е.**).

**Скриншот:** создание проекта и свойства проекта.

---

## 3. Ввод отделов и ресурсов компании

### 3.1. Отделы

1. Перейдите в раздел **«Отделы»**.
2. Нажмите **«Добавить»**.
3. Создайте, например, отдел **«Офис / ИТ»** (название может быть любым учебным).

### 3.2. Ресурсы

1. Перейдите в раздел **«Ресурсы»**.
2. Добавьте ресурс:
   - **Имя:** `Сервер`
   - **Отдел:** созданный выше
   - **Критичность ресурса D:** `100` (у.е.)
3. Сохраните ресурс.

Для учебной работы по бланку достаточно **одного** ресурса — сервера. Дополнительные ПК добавлять не обязательно, если преподаватель не просит расширить модель.

**Скриншот:** список ресурсов с критичностью 100.

---

## 4. Ввод угроз

1. Откройте раздел **«Угрозы»**.
2. Добавьте три угрозы (можно выбрать из каталога предопределённых или создать вручную с теми же названиями).

| № | Название угрозы в проекте |
|---|---------------------------|
| Угроза 1 | Неавторизованное проникновение нарушителя внутрь охраняемого периметра (одного из периметров) |
| Угроза 2 | Неавторизованная модификация информации в системе электронной почты, хранящейся на ресурсе |
| Угроза 3 | Разглашение конфиденциальной информации сотрудниками компании |

Подсказки по дереву каталога ГРИФ (если ищете готовые формулировки):
- Угроза 1: *Физические угрозы человека → На ресурс → …проникновение…*
- Угроза 2: *Локальные программные угрозы → На информацию… → …электронной почты…*
- Угроза 3: *Угрозы персонала / шпионаж → Разглашение конфиденциальной информации…*

**Скриншот:** список добавленных угроз.

---

## 5. Ввод уязвимостей

В разделе **«Уязвимости»** (или при привязке к угрозе — в зависимости от версии интерфейса) добавьте шесть уязвимостей:

### Для угрозы 1
1. Отсутствие регламента доступа в помещения с ресурсами, содержащими ценную информацию  
2. Отсутствие системы наблюдения (видеонаблюдение, сенсоры и т.д.) за объектом (или существующая система наблюдения охватывает не все важные объекты)

### Для угрозы 2
1. Отсутствие авторизации для внесения изменений в систему электронной почты  
2. Отсутствие регламента работы с системой криптографической защиты электронной корреспонденции

### Для угрозы 3
1. Отсутствие соглашений о конфиденциальности  
2. Распределение атрибутов безопасности (ключи доступа, шифрования) между несколькими доверенными сотрудниками

Если уязвимость выбирается из каталога — найдите максимально близкую формулировку; если нет — создайте пользовательскую с точным текстом из бланка.

**Скриншот:** перечень уязвимостей.

---

## 6. Связи: ресурс ↔ угрозы ↔ уязвимости + P(V) и ER

Это главный шаг. Именно здесь задаются числа для расчёта.

1. Откройте раздел **«Связи»** (или аналог: связи ресурса с угрозами).
2. Выберите ресурс **«Сервер»**.
3. **Добавьте** на ресурс все три угрозы.
4. Для каждой угрозы добавьте две её уязвимости.
5. Для **каждой пары** «угроза / уязвимость» введите:

| Угроза / Уязвимость | P(V), % | ER, % |
|---------------------|---------|-------|
| У1 / Уязв.1 | 50 | 60 |
| У1 / Уязв.2 | 20 | 60 |
| У2 / Уязв.1 | 60 | 40 |
| У2 / Уязв.2 | 10 | 40 |
| У3 / Уязв.1 | 10 | 80 |
| У3 / Уязв.2 | 80 | 80 |

Пояснения полей:
- **P(V)** — вероятность реализации угрозы через данную уязвимость в течение года, %;
- **ER** — критичность реализации угрозы (через уязвимость), %.

Проверьте, что все 6 пар заполнены и привязаны именно к **Серверу**.

**Скриншоты (обязательно):**
- связи ресурса «Сервер»;
- пример заполнения одной пары (например У1/Уязв.1 = 50%/60%);
- общий вид всех связей.

## 7. Расчёт и создание отчёта в ГРИФ

1. Запустите расчёт (кнопка расчёта / обновления модели — в зависимости от версии; часто расчёт выполняется при формировании отчёта).
2. Меню **«Отчёт» → «Создать отчёт»** (или «Сформировать отчёт»).
3. Включите в отчёт:
   - инвентаризацию ресурсов;
   - значения риска по ресурсу;
   - перечень уязвимостей, влияющих на риск;
   - при наличии — остаточный риск и эффективность контрмер.
4. Сохраните/экспортируйте отчёт (HTML/DOC/встроенный просмотр — что доступно в демо).

Ожидаемый ориентир (должен совпасть с ручным расчётом из задания №1):
- общий уровень угроз по ресурсу **CThR ≈ 0,851**;
- риск ресурса **R ≈ 85,11 у.е.** (при D = 100).

Если числа сильно расходятся — перепроверьте `P(V)`, `ER` и привязки угроз/уязвимостей.

**Скриншоты:**
- окно/мастер создания отчёта;
- фрагмент отчёта с риском по «Серверу»;
- (опционально) список уязвимостей-причин риска.

---

## 8. (Опционально) Контрмеры и остаточный риск

Если преподаватель просит или остаётся время:

1. Добавьте 1–2 контрмеры, закрывающие самые «тяжёлые» уязвимости  
   (для бланка логично закрыть **У3/Уязв.2** с P(V)=80% и ER=80%).
2. Пересчитайте риск.
3. Зафиксируйте:
   - риск до контрмер;
   - остаточный риск;
   - снижение риска / эффективность.

**Скриншот:** сравнение риска до/после.

## 10. Частые проблемы

| Проблема | Что сделать |
|----------|-------------|
| ГРИФ не стартует | Сначала запустить сервер DSO; проверить, что демо установлено полностью |
| Нет пунктов каталога угроз | Создать угрозы/уязвимости вручную с текстами из бланка |
| Риск = 0 | Не заполнены связи или P(V)/ER = 0 |
| Риск сильно отличается от ~85 | Перепутаны проценты, не все 6 пар, неверный D |
| Старое ПО на новой ОС | Только VM с Windows XP / совместимой средой |
