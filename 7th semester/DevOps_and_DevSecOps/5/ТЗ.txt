На пятой практике вам необходимо подключить Secret Scanning к существующему CI/CD-пайплайну GitLab, настроить автоматический поиск секретов в исходном коде и истории Git, а затем научиться удалять обнаруженные секреты из истории репозитория. В качестве инструмента используете Kingfisher. В качестве проекта для этой практики используете приложения со второй практики

Задание по шагам:
1) Установить и настроить Kingfisher. Он должен запускаться через GitLab Runner
2) Добавить в существующий файл .gitlab-ci.yml отдельное задание для запуска Kingfisher. Проверка должна выполняться до этапа deploy. Настроить получение полной истории коммитов и сохранение JSON-отчёта в артефактах пайплайна
3) Настроить правила обнаружения секретов. Помимо встроенных правил Kingfisher, создать минимум одно собственное правило для поиска тестовых API-ключей или токенов
4) Подключить Kingfisher к ранее развёрнутому DefectDojo. Для приложения со второй практики создать отдельный Product и Engagement, а внутри него Test для результатов Kingfisher. Настроить автоматическую передачу JSON-отчётов через API и последующее обновление результатов через Reimport. Отчёты должны передаваться в DefectDojo даже при обнаружении секретов и блокировке пайплайна
5) Намеренно добавить в исходный код или конфигурационный файл один тестовый секрет. Создать коммит и отправить изменения в GitLab. Запустить пайплайн и убедиться, что Kingfisher обнаружил секрет, информация о нём появилась в DefectDojo, а развёртывание приложения было заблокировано. По результатам скана нужно определить, в каком файле и коммите находится секрет, каким правилом он обнаружен и почему инструмент посчитал его потенциальной утечкой
6) Удалить тестовый секрет из исходного кода, создать новый коммит и повторно запустить пайплайн - Kingfisher должен в любом случае обнаружить секрет (так как он сохранился в истории предыдущих коммитов)
7) Используя git-filter-repo, переписать историю репозитория таким образом, чтобы удалить из неё тестовый секрет. Перед переписыванием истории создать резервную копию репозитория. Отправить очищенную историю в GitLab и проверить результат на новом клоне репозитория
8) Повторно запустить CI/CD-пайплайн. Kingfisher больше не должен обнаруживать тестовый секрет в проверяемой истории Git
9) Повторно отправить результаты Kingfisher в DefectDojo через Reimport. Настроить автоматическое закрытие уязвимостей, которые больше не обнаруживаются при повторном сканировании. Проверьте, что после очистки истории ранее обнаруженная уязвимость получила статус Mitigated, а история её обнаружения и исправления сохранилась
